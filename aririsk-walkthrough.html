01 · Data Profiling Step 1

Data Profiling · frame the scope first

The analyst reflex: check volumes, time bounds, coverage and quality before touching a model. The constraints shape everything — a single tax-arrears snapshot, not a time series. Knowing your data's limits from the start is what separates an analysis from an opinion.

Volumes + time rangeCoverage per companyReport density
-- =========================================================================
-- 01 — DATA PROFILE : frame the scope before analysing
-- The data-profiler reflex : volumes, bounds, quality, coverage.
-- =========================================================================

-- 1.1 --- Overview : volumes + temporal bounds ----------------------------
SELECT
  (SELECT COUNT(*)         FROM raw.companies)                  AS n_companies,
  (SELECT COUNT(*)         FROM raw.annual_reports)             AS n_reports,
  (SELECT COUNT(DISTINCT reg_code) FROM raw.annual_reports)     AS firms_with_reports,
  (SELECT COUNT(*)         FROM marts.distress_label
     WHERE is_distressed)    AS n_distressed,
  (SELECT COUNT(*)         FROM marts.distress_label
     WHERE is_bankrupt)    AS n_bankruptcies,
  (SELECT MIN(report_year) FROM raw.annual_reports)             AS min_year,
  (SELECT MAX(report_year) FROM raw.annual_reports)             AS max_year,
  (SELECT COUNT(DISTINCT snapshot_date) FROM raw.tax_arrears)   AS n_tax_snapshots;

-- Observed : 375,886 companies, 7 years of reports (2019-2025),
-- a single tax-arrears snapshot (2026-08-10).

-- 1.2 --- Breakdown by legal form + status ---------------------------------
SELECT legal_form, status_text, COUNT(*) AS n
FROM raw.companies
GROUP BY legal_form, status_text
ORDER BY n DESC
LIMIT 20;

-- 1.3 --- Sector breakdown (EMTAK section), latest year ---------------------
SELECT emtak_section, COUNT(DISTINCT reg_code) AS n_companies
FROM marts.ratios
WHERE report_year = (SELECT MAX(report_year) FROM marts.ratios)
GROUP BY emtak_section
ORDER BY n_companies DESC;

-- 1.4 --- "Reports per company" coverage (who has how many years) -----------
SELECT n_reports, COUNT(*) AS n_companies
FROM (
  SELECT reg_code, COUNT(*) AS n_reports
  FROM raw.annual_reports
  GROUP BY reg_code
) t
GROUP BY n_reports
ORDER BY n_reports;

-- 1.5 --- Year-of-report density --------------------------------------------
SELECT report_year,
       COUNT(DISTINCT reg_code) AS n_companies,
       COUNT(*)                 AS n_reports
FROM raw.annual_reports
GROUP BY report_year
ORDER BY report_year;
02 · Financial Ratios Step 2

Financial Ratios · rebuild, then benchmark

The heart of the credit job: reconstruct the ratios by hand from the balance sheet (with NULLIF guards against divide-by-zero), then position a company against its sector's P10 / P50 / P90. A liquidity ratio under the sector's 10th percentile is a real signal, not a number.

Margin / ROA / solvencyYoY growth via LAGSector benchmark P10/P50/P90
-- =========================================================================
-- 02 — FINANCIAL RATIOS : rebuild the ratios in SQL + position a firm
-- The heart of the credit job : rebuild ratios from the balance sheet, then
-- compare a company against its sector (P10 / P50 / P90 benchmark).
-- =========================================================================

-- 2.1 --- Rebuild the ratios by hand from the balance sheet (NULLIF guards) --
SELECT
  reg_code, report_year, revenue,
  ROUND(100.0 * net_profit        / NULLIF(revenue,0), 2) AS net_margin_pct,
  ROUND(100.0 * operating_profit  / NULLIF(revenue,0), 2) AS op_margin_pct,
  ROUND(100.0 * net_profit        / NULLIF(assets,0), 2)  AS roa_pct,
  ROUND(100.0 * equity            / NULLIF(assets,0), 2)  AS solvency_pct,
  ROUND(current_assets / NULLIF(current_liabilities,0), 2) AS current_ratio,
  ROUND(100.0 * (current_liabilities + non_current_liabilities)
        / NULLIF(assets,0), 2)                            AS leverage_pct
FROM raw.annual_reports
WHERE NOT COALESCE(consolidated, false)   -- exclude consolidated accounts
  AND assets > 0
  AND report_year = 2024
ORDER BY reg_code
LIMIT 30;

-- 2.2 --- Revenue growth year-over-year (LAG = a window) --------------------
-- LAG() grabs the previous row's value within the partition (here by company,
-- ordered by year) : the building block of any "evolution" feature.
WITH r AS (
  SELECT reg_code, report_year, revenue,
         LAG(revenue) OVER (PARTITION BY reg_code
                            ORDER BY report_year) AS rev_prev
  FROM raw.annual_reports
  WHERE NOT COALESCE(consolidated, false) AND revenue > 0
)
SELECT reg_code, report_year, revenue, rev_prev,
       ROUND(100.0 * (revenue - rev_prev) / NULLIF(rev_prev,0), 1) AS growth_pct
FROM r
WHERE rev_prev IS NOT NULL
ORDER BY reg_code, report_year;

-- 2.3 --- Position one company vs its sector (benchmark) --------------------
-- Compare the firm's ratios to the sector+year P10 / P50 / P90 benchmarks.
-- Signal : a liquidity ratio UNDER the P10 = elevated risk.
SELECT
  r.reg_code, r.report_year, r.emtak_section,
  r.liquidity        AS my_liquidity,
  b.liquidite_p10, b.liquidite_p50, b.liquidite_p90,
  CASE
    WHEN r.liquidity < b.liquidite_p10 THEN 'BELOW P10 (elevated risk)'
    WHEN r.liquidity < b.liquidite_p50 THEN 'below median'
    ELSE                                'above median'
  END AS liquidity_position,
  r.solvency, b.solvabilite_p50,
  r.roa, b.roa_p50
FROM marts.ratios r
JOIN marts.benchmarks_emtak b
  ON b.emtak_section = r.emtak_section
 AND b.report_year   = r.report_year
WHERE r.reg_code = 10051907;   -- TODO : replace with a real Estonian reg_code
03 · Cohort & Vintage Step 3

Cohort & Vintage · risk across time and segments

The credit-risk reflex: read risk in the time dimension (creation-year cohort) and across segments (sector, size, legal form). Opens with the caveat to name out loud — older cohorts have had more years to become distressed, so their rate is mechanically higher. That vintage effect is exactly what you must mention.

Distress rate by cohortRisk by EMTAK sectorTax-debt → distress bridge
-- =========================================================================
-- 03 — COHORT / VINTAGE : default rate by cohort and segment
-- The credit-risk reflex : read risk in the time dimension (creation-year
-- cohort) and across segments (sector, size, legal form).
-- =========================================================================

-- 3.1 --- Distress rate by creation-year cohort -----------------------------
-- [CAVEAT TO NAME OUT LOUD] Older cohorts have had more years to become
-- distressed, so they're more exposed and mechanically higher. That vintage
-- effect must be mentioned.
SELECT
  EXTRACT(YEAR FROM c.first_registration_date)::int AS cohort_year,
  COUNT(*)                                         AS n_companies,
  COUNT(*) FILTER (WHERE d.is_distressed)            AS n_distressed,
  ROUND(100.0 * COUNT(*) FILTER (WHERE d.is_distressed)
        / NULLIF(COUNT(*),0), 2)                   AS distress_rate_pct
FROM raw.companies c
JOIN marts.distress_label d ON d.reg_code = c.reg_code
WHERE c.first_registration_date IS NOT NULL
GROUP BY cohort_year
ORDER BY cohort_year;

-- 3.2 --- Risk by sector (EMTAK) : who is risky? ------------------------------
SELECT
  r.emtak_section,
  COUNT(DISTINCT r.reg_code)                                  AS n,
  COUNT(DISTINCT r.reg_code) FILTER (WHERE d.is_distressed)     AS n_distressed,
  ROUND(100.0 * COUNT(DISTINCT r.reg_code) FILTER (WHERE d.is_distressed)
        / NULLIF(COUNT(DISTINCT r.reg_code),0), 2)            AS distress_rate_pct
FROM marts.ratios r
JOIN marts.distress_label d ON d.reg_code = r.reg_code
WHERE r.report_year = (SELECT MAX(report_year) FROM marts.ratios)
GROUP BY r.emtak_section
HAVING COUNT(DISTINCT r.reg_code) > 50            -- ignore tiny samples
ORDER BY distress_rate_pct DESC;

-- 3.3 --- Risk by legal form --------------------------------------------------
SELECT
  d.legal_form,
  COUNT(*) AS n,
  COUNT(*) FILTER (WHERE d.is_distressed) AS n_distressed,
  ROUND(100.0 * COUNT(*) FILTER (WHERE d.is_distressed)
        / NULLIF(COUNT(*),0), 2) AS rate_pct
FROM marts.distress_label d
GROUP BY d.legal_form
HAVING COUNT(*) > 20
ORDER BY rate_pct DESC;

-- 3.4 --- Risk by size band (revenue). latest year ----------------------------
SELECT
  CASE
    WHEN r.revenue IS NULL        THEN 'unknown'
    WHEN r.revenue < 100000       THEN 'micro (<100k)'
    WHEN r.revenue < 2000000      THEN 'small (100k-2M)'
    WHEN r.revenue < 10000000     THEN 'medium (2M-10M)'
    ELSE                          'large (>10M)'
  END AS size_band,
  COUNT(DISTINCT r.reg_code)                                  AS n,
  COUNT(DISTINCT r.reg_code) FILTER (WHERE d.is_distressed)     AS n_distressed,
  ROUND(100.0 * COUNT(DISTINCT r.reg_code) FILTER (WHERE d.is_distressed)
        / NULLIF(COUNT(DISTINCT r.reg_code),0), 2)            AS rate_pct
FROM marts.ratios r
JOIN marts.distress_label d ON d.reg_code = r.reg_code
WHERE r.report_year = (SELECT MAX(report_year) FROM marts.ratios)
GROUP BY size_band
ORDER BY rate_pct DESC;

-- 3.5 --- The tax-debt -> distress bridge -------------------------------------
-- The information value of the MTA arrears : how often does a company with
-- tax debt end up distressed?
SELECT
  has_tax_debt,
  COUNT(*)                      AS n,
  COUNT(*) FILTER (WHERE is_distressed) AS n_distressed,
  ROUND(100.0 * COUNT(*) FILTER (WHERE is_distressed)
        / NULLIF(COUNT(*),0), 2) AS distress_rate_pct
FROM marts.distress_label
GROUP BY has_tax_debt;

-- 3.6 --- Age of distressed companies (distribution) ---------------------------
SELECT
  EXTRACT(YEAR FROM AGE(CURRENT_DATE, first_registration_date))::int AS age_years,
  COUNT(*) AS n_distressed
FROM marts.distress_label
WHERE is_distressed
GROUP BY age_years
ORDER BY age_years;
04 · Feature Engineering Step 4

Feature Engineering · build the training table

Assemble ratios + LAG evolution + sector benchmark + target into the table a PD model is trained on. The leading-indicator columns — margin falling, liquidity falling, leverage rising, liquidity under benchmark — capture deterioration, which is what predicts default. Plus a run-length pattern for consecutive loss years.

Panel company × yearLagged ratios (evolution)Consecutive-loss runs
-- =========================================================================
-- 04 — PD FEATURE ENGINEERING : build the training table
-- Assemble (ratios + LAG evolution + sector benchmark + target) to feed a
-- probability-of-default model in Python.
-- =========================================================================

-- 4.1 --- Company x year panel : ratios + LAG + benchmark ---------------------
WITH feat AS (
  SELECT
    r.reg_code, r.report_year, r.emtak_section, r.revenue,
    r.net_margin, r.op_margin, r.roa, r.solvency, r.liquidity,
    r.debt_to_assets, r.revenue_growth,
    -- governance proxy : filing delay (days between close and filing)
    (r.filing_date - r.period_end) AS filing_delay_days,
    -- LAG : the same ratios, one year earlier (change is a strong signal)
    LAG(r.net_margin) OVER (PARTITION BY r.reg_code
                             ORDER BY r.report_year) AS net_margin_prev,
    LAG(r.liquidity)   OVER (PARTITION BY r.reg_code
                             ORDER BY r.report_year) AS liquidity_prev,
    LAG(r.roa)         OVER (PARTITION BY r.reg_code
                             ORDER BY r.report_year) AS roa_prev,
    LAG(r.debt_to_assets) OVER (PARTITION BY r.reg_code
                             ORDER BY r.report_year) AS leverage_prev,
    -- sector benchmark (to capture relative positioning)
    b.liquidite_p10, b.liquidite_p50,
    -- target (default proxy)
    d.is_distressed
  FROM marts.ratios r
  LEFT JOIN marts.benchmarks_emtak b
    ON b.emtak_section = r.emtak_section
   AND b.report_year   = r.report_year
  LEFT JOIN marts.distress_label d ON d.reg_code = r.reg_code
)
SELECT
  *,
  -- Leading indicators (deteriorations) — the features that predict ----------
  (net_margin < net_margin_prev)         AS margin_declining,
  (liquidity < liquidity_prev)            AS liquidity_declining,
  (roa < roa_prev)                        AS profitability_declining,
  (debt_to_assets > leverage_prev)       AS leverage_rising,
  (liquidity < liquidite_p10)             AS below_benchmark_liquidity
FROM feat
WHERE report_year = (SELECT MAX(report_year) FROM marts.ratios);  -- latest year

-- 4.2 --- Consecutive loss years (persistence of losses) ----------------------
-- Spot companies that string losses together : a risk signal.
WITH pertes AS (
  SELECT reg_code, report_year, net_profit,
         (net_profit < 0)                              AS in_loss,
         LAG(net_profit) OVER (PARTITION BY reg_code
                               ORDER BY report_year)   AS np_prev
  FROM raw.annual_reports
  WHERE NOT COALESCE(consolidated, false)
),
series AS (
  SELECT reg_code, report_year, in_loss,
         -- break the run whenever it returns to profit -> segments of losses
         SUM(CASE WHEN in_loss THEN 0 ELSE 1 END)
           OVER (PARTITION BY reg_code ORDER BY report_year) AS grp
  FROM pertes
)
SELECT reg_code, COUNT(*) AS consecutive_loss_years
FROM series
WHERE in_loss
GROUP BY reg_code, grp
ORDER BY consecutive_loss_years DESC
LIMIT 30;

05 · Altman-Z Score Step 5

Altman-Z Score · an explainable score, in SQL

A simple but explainable credit score computed entirely in SQL and then tested against the target. The point: does the score actually separate distressed companies? The confusion-matrix query is the root of every PD model evaluation — AUC, precision, sensitivity. This is the SQL → ML bridge.

Altman-Z from balance sheetScore split vs targetConfusion matrix
-- =========================================================================
-- 05 — SCORING : an Altman-Z style credit score in SQL, then validated
-- A simple, explainable score — tested against the target to see whether it
-- actually separates distressed firms. The SQL -> ML bridge.
-- =========================================================================

-- 5.1 --- Altman-Z adapted to the present balance sheet ----------------------
-- Z = 1.2*X1 + 1.4*X2 + 3.3*X3 + 0.6*X4 + 1.0*X5
-- X1 = working capital / assets ; X2 = retained earnings / assets ;
-- X3 = operating profit / assets ; X4 = equity / liabilities ;
-- X5 = sales / assets.
WITH z AS (
  SELECT reg_code, report_year,
         (current_assets - current_liabilities)          AS wc,
         retained_earnings                               AS re,
         operating_profit                                AS ebit,
         equity                                          AS eq,
         (current_liabilities + non_current_liabilities) AS liabilities,
         revenue                                         AS sales,
         assets                                          AS assets
  FROM raw.annual_reports
  WHERE NOT COALESCE(consolidated, false) AND assets > 0
)
SELECT
  reg_code, report_year,
  ROUND(1.2*(wc/assets) + 1.4*(re/assets) + 3.3*(ebit/assets)
        + 0.6*(eq/liabilities) + 1.0*(sales/assets), 2) AS z_score,
  CASE
    WHEN 1.2*(wc/assets) + 1.4*(re/assets) + 3.3*(ebit/assets)
          + 0.6*(eq/liabilities) + 1.0*(sales/assets) > 2.99 THEN 'green'
    WHEN 1.2*(wc/assets) + 1.4*(re/assets) + 3.3*(ebit/assets)
          + 0.6*(eq/liabilities) + 1.0*(sales/assets) >= 1.81 THEN 'grey'
    ELSE 'red'
  END AS z_zone
FROM z
WHERE report_year = (SELECT MAX(report_year) FROM raw.annual_reports);

-- 5.2 --- Does the score separate the target? (mean / median per group) -------
-- If the score is useful, distressed firms should have a markedly lower Z.
WITH z AS (
  SELECT a.reg_code, a.report_year,
    1.2*((a.current_assets - a.current_liabilities)/a.assets)
    + 1.4*(a.retained_earnings/a.assets)
    + 3.3*(a.operating_profit/a.assets)
    + 0.6*(a.equity/(a.current_liabilities + a.non_current_liabilities))
    + 1.0*(a.revenue/a.assets) AS z_score
  FROM raw.annual_reports a
  WHERE NOT COALESCE(a.consolidated, false) AND a.assets > 0
    AND a.report_year = (SELECT MAX(report_year) FROM raw.annual_reports)
)
SELECT d.is_distressed, COUNT(*) AS n,
       ROUND(AVG(z.z_score), 3) AS z_mean,
       ROUND(PERCENTILE_CONT(0.5) WITHIN GROUP (ORDER BY z.z_score), 3) AS z_median
FROM z
JOIN marts.distress_label d ON d.reg_code = z.reg_code
GROUP BY d.is_distressed;

-- 5.3 --- Confusion matrix of the score vs the target (simple threshold) ------
-- Convert the score to a binary prediction (threshold z<1.81 = "default"),
-- compare to the true target -> TN / FP / FN / TP. The root of every PD
-- model evaluation (AUC, precision, sensitivity).
WITH z AS (
  SELECT a.reg_code,
    1.2*((a.current_assets - a.current_liabilities)/a.assets)
    + 1.4*(a.retained_earnings/a.assets)
    + 3.3*(a.operating_profit/a.assets)
    + 0.6*(a.equity/(a.current_liabilities + a.non_current_liabilities))
    + 1.0*(a.revenue/a.assets) AS z_score
  FROM raw.annual_reports a
  WHERE NOT COALESCE(a.consolidated, false) AND a.assets > 0
    AND a.report_year = (SELECT MAX(report_year) FROM raw.annual_reports)
)
SELECT
  (z.z_score < 1.81) AS pred_default,
  d.is_distressed     AS actual_default,
  COUNT(*)          AS n
FROM z
JOIN marts.distress_label d ON d.reg_code = z.reg_code
GROUP BY 1, 2
ORDER BY 1, 2;
-- Interpretation : (pred=F, actual=T) = false negatives -> the score missed defaults.
06 · Time Intelligence Step 6

Time Intelligence · the advanced window functions

The patterns that appear everywhere in risk analytics: a 3-year rolling mean to smooth noise, RANK / PERCENT_RANK inside a sector to see who's the most indebted of their branch, FIRST_VALUE vs LAST_VALUE to detect deterioration, and the classic run-length for 3+ consecutive loss years.

Rolling 3-year meanRANK / PERCENT_RANK by sectorFirst vs last value
-- =========================================================================
-- 06 — WINDOW / TIME INTELLIGENCE : the advanced windows
-- These patterns appear everywhere in risk analysis. Worth knowing by heart.
-- =========================================================================

-- 6.1 --- 3-year rolling mean of net margin -----------------------------------
-- "ROWS BETWEEN n PRECEDING AND CURRENT ROW" : a moving average that smooths
-- noise to reveal the underlying trend.
WITH r AS (
  SELECT reg_code, report_year, revenue, net_profit,
         ROUND(100.0 * net_profit / NULLIF(revenue,0), 2) AS margin
  FROM raw.annual_reports
  WHERE NOT COALESCE(consolidated, false) AND revenue > 0
)
SELECT reg_code, report_year, margin,
       ROUND(AVG(margin) OVER (PARTITION BY reg_code ORDER BY report_year
                               ROWS BETWEEN 2 PRECEDING AND CURRENT ROW), 2)
         AS margin_ma3
FROM r
ORDER BY reg_code, report_year;

-- 6.2 --- Rank and percentile of leverage WITHIN the sector ------------------
-- RANK / PERCENT_RANK by sector : who is the most indebted of their branch?
SELECT reg_code, emtak_section, debt_to_assets,
       RANK()       OVER (PARTITION BY emtak_section
                          ORDER BY debt_to_assets DESC) AS leverage_rank,
       PERCENT_RANK() OVER (PARTITION BY emtak_section
                          ORDER BY debt_to_assets DESC) AS leverage_pct
FROM marts.ratios
WHERE report_year = (SELECT MAX(report_year) FROM marts.ratios)
ORDER BY emtak_section, leverage_rank;

-- 6.3 --- Deterioration : latest report vs first report -----------------------
-- FIRST_VALUE vs LAST_VALUE : measure whether the firm has degraded since its
-- first available report.
WITH r AS (
  SELECT reg_code, report_year, roa, solvency, liquidity
  FROM marts.ratios
)
SELECT
  reg_code, report_year,
  FIRST_VALUE(roa) OVER (PARTITION BY reg_code ORDER BY report_year) AS roa_first,
  LAST_VALUE(roa)  OVER (PARTITION BY reg_code ORDER BY report_year
                         ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING)
                                                            AS roa_last,
  (LAST_VALUE(roa) OVER (PARTITION BY reg_code ORDER BY report_year
                         ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING)
   - FIRST_VALUE(roa) OVER (PARTITION BY reg_code ORDER BY report_year)) AS roa_delta
FROM r
WHERE report_year = (SELECT MAX(report_year) FROM marts.ratios)
ORDER BY roa_delta;

-- 6.4 --- Companies with 3+ consecutive negative years ------------------------
-- The classic "run" : detect long sequences of losses.
WITH pertes AS (
  SELECT reg_code, report_year, (net_profit < 0) AS in_loss
  FROM raw.annual_reports
  WHERE NOT COALESCE(consolidated, false)
),
series AS (
  SELECT reg_code, report_year, in_loss,
         SUM(CASE WHEN in_loss THEN 0 ELSE 1 END)
           OVER (PARTITION BY reg_code ORDER BY report_year) AS grp
  FROM pertes
)
SELECT reg_code, COUNT(*) AS consecutive_loss_years
FROM series
WHERE in_loss
GROUP BY reg_code, grp
HAVING COUNT(*) >= 3
ORDER BY consecutive_loss_years DESC;

Methodology &
Limits

The problem

Anticipate payment default on 375,000+ Estonian companies. Target = distress proxy, not bankruptcy — the latter is a 0.18% event, rare and already too late.

The method

Six SQL passes, each a credit-analyst reflex: profile the data, rebuild ratios, benchmark vs sector, read risk in cohorts, engineer PD features, score & validate. Window functions and LAG model deterioration — the leading indicators of default.

What the proxy teaches

AUC, not accuracy. A model that predicted "nobody defaults" would be 99.8% accurate and useless.

Honest limitations

  • Target is point-in-time (Aug 2026 snapshot) — no fine-grained default history.
  • Tax arrears is a single snapshot — the real time axis is the annual reports.
  • Default is rare — so I evaluate with AUC, never accuracy.
  • TimesFM forecast is a prototype — a forward-looking extra layer, not the model.

SQL Skills Demonstrated

PostgreSQL on Neon. Python (pandas, XGBoost, SHAP) for the PD model. TimesFM-3 for the forward-looking layer.
